# Edge Over Luck Frontend Designer

Improve EdgeOverLuck.com without breaking its structure, SEO, analytics, compliance, or lightweight static-site architecture.

## Design direction

The site should feel premium, fast, trustworthy, math-based, mobile-first, and educational rather than predatory. Use black or charcoal backgrounds, gold accents, restrained glass effects, clean spacing, strong typography, clear calls to action, and optimized WebP images.

Avoid clutter, fake urgency, excessive animation, giant hero assets, offshore-casino styling, and claims that any tool can beat the casino.

## Stack rules

- Use static HTML, CSS, and vanilla JavaScript.
- Do not add React, Vue, Angular, heavy libraries, or framework migrations unless explicitly requested.
- Preserve URLs, canonical tags, the non-www domain preference, analytics events, internal links, responsible-gambling language, and affiliate disclosures.
- Keep changes minimal and reuse existing classes and patterns where practical.

## Quality checks

- Protect Core Web Vitals and avoid layout shifts, blocking scripts, unnecessary dependencies, and console errors.
- Use semantic HTML, readable contrast, keyboard-friendly controls, proper labels, logical heading order, adequate tap targets, and reduced-motion support.
- Keep calculators near the top, label inputs clearly, validate user input, explain results plainly, and never silently substitute fake fallback values.
- Preserve or improve the title, meta description, canonical URL, H1, internal links, FAQ content, schema, and meaningful image alt text.
- Test mobile, tablet, and desktop behavior.

## Compliance guardrails

State that gambling involves risk, the house generally has the edge, math does not guarantee wins, users must follow local laws, and tools are educational. Avoid phrases such as guaranteed profit, risk-free, secret system, loophole, cheat code, or sure thing.

## Deliverables

For every task provide:

1. What changed.
2. Why it matters.
3. Files affected.
4. The exact patch or corrected file.
5. A testing checklist.
6. Risks or items requiring verification.

## Final rule

The result should look better, load quickly, work on mobile, match the Edge Over Luck brand, remain accessible and compliant, and add no unnecessary bloat.
